# 03. Business data, placeholders and release checks

## One source of truth
`content/shared/site.json` holds the facts about the business **once**:

```
brand, legalName, domain, whatsappNumber (digits), phoneDisplay, email,
verified (false until a person confirms), city, country, address, geo,
openingHours, social
```

Everything reads it:

- Texts: `{{email}}`, `{{phone}}`, `{{domain}}`, `{{city}}` in the JSON files (`lib/content.ts`, function `fill`).
- WhatsApp links: `getWhatsAppUrl()` in `lib/content.ts`.
- Forms: `components/sections/ContactPage/ContactForm.tsx` imports `site.email`.
- SEO data (Google): `lib/seo.ts` builds the business JSON-LD from it, so page and Google data cannot disagree.
- Public address: `siteUrl` in `lib/seo.ts` (`https://<domain>` unless `NEXT_PUBLIC_SITE_URL` is set).

To change the phone: edit `site.json` only.

## The placeholder check: `scripts/check-site-data.mjs`
It scans `site.json` and every content file for fake values (patterns: fake email domain, fake phone, `TODO`, "Add stack...") and lists texts that are still `draft` in `review-status.json`.

- `npm run check:site` prints a list and always succeeds (development is never blocked).
- `npm run check:release` is strict: exit code 1 if anything is left. It also needs `"verified": true` in `site.json`.
- `npm run build:release` runs the strict check first, then the image budget, the build and the SEO lint. The GitHub deploy workflow uses it, so a build with a fake number cannot be uploaded.
- Format hints like `+212 6XX XX XX XX` in form fields are allowed (they are not numbers).

Tests: `scripts/check-site-data.test.ts`.

## Related files
`content/review-status.json` (per language and file: draft or reviewed), `docs/OWNER-CHECKLIST.md` (what to send), `docs/content-audit.md` (claims to verify, generated by `scripts/claims-audit.mjs`).
